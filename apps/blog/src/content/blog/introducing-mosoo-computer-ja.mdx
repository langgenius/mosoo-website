エージェントと長く仕事をするほど、前回の続きから始めてほしくなります。ファイルが残っていて、ツールは設定済み。自分の仕事の進め方も、毎回最初から説明せずに済むことを期待するようになります。

[Mosoo Computer](https://computer.mosoo.ai/) は、その期待から生まれました。エージェントに、必要な状態を蓄積できるクラウド上の作業環境を用意し、普段使っているチャットからアクセスできるようにします。

## 能力を呼び出すことから、エージェントを育てることへ

以前公開した[「2種類のエージェント：Pet と Cattle」](https://mosoo.ai/blog/ja/two-kinds-of-agents-pet-and-cattle)では、エージェントに対する二つの期待を取り上げました。一つは、ある能力を繰り返し呼び出し、次のタスクを新しい実行インスタンスに任せること。もう一つは、同じエージェントと継続的に仕事をし、その作業の文脈を積み重ねることです。

Mosoo Computer が向き合うのは、後者です。

2年間使ったパソコンは、買ったばかりのパソコンより使いやすいことがあります。そこには、自分のファイル、ツール、仕事の進め方が蓄積されているからです。長く一緒に働くエージェントにとっても、その蓄積は大切です。モデルが推論を担い、作業環境が成果を保存し、ツールを使い、仕事を続ける場所になります。

ここでいう「育てる」は、会話のたびにモデルを学習させるという意味ではありません。ファイルや設定、ランタイムが保存するメモリーを残し、次の仕事に役立てることです。メモリーの使われ方は、選んだランタイムによって異なります。

## 継続する作業環境を、一台の Computer に

Mosoo Computer では、エージェントに名前を付け、ランタイムとマシンスペックを選び、モデルへのアクセスを設定します。現在の作成画面では、Codex、Hermes、OpenClaw を選択できます。

会話を始めるたびに、作業環境を作り直す必要がないことが重要です。ファイルとランタイムの状態には保存先があり、個々の会話は Session として記録されます。チャネル接続は、その環境への入口になります。

永続性は、コンテナのプロセスが止まらずに動き続けることとは異なります。現在の製品では、スリープ中はコンテナのプロセスが停止する一方、ワークスペースのファイル、ランタイムの状態、Session、チャネルの接続設定は保持されると明示しています。プロセスメモリーと一時ディスクは保持されません。次の Web またはチャネルからのリクエストが復帰のきっかけになります。

残したいのは、仕事のつながりです。

## いつものチャットを入口にする

Web Console は、現在のサインイン情報で利用できます。普段のコミュニケーションにエージェントを加えるには、Channels から Telegram、Slack、Discord、飛書 / Lark を接続します。

チャネルが決めるのは、メッセージの受け取り先と返信先です。その先には、選択したエージェントと作業環境があります。チャットの入口を増やすたびに、別の Computer を用意する必要はありません。

ただし、同じエージェントにつながることと、すべての会話履歴が一つになることは別です。現在の製品では、外部の会話ごとに個別の Session が作られます。チャネルをまたいで使う情報は、ワークスペースに明示的に保存するか、ランタイムが対応するメモリー機能を使って残します。別のチャネルに過去の全メッセージが自動で引き継がれるとは限りません。

## ランタイムとモデルへの接続方法を選ぶ

ランタイムは、推論、ツール呼び出し、タスクの実行ループを組み立てます。モデルへの接続設定は、どのモデルを、どの認証方法で利用するかを決めます。

Mosoo Computer では、それぞれを別の場所で設定します。Model Access では、自分のモデルプロバイダーの API Key を管理します。これが BYOK です。各エージェントは、自身の Settings でモデルの接続元とモデルを選択します。対応するランタイムでは、Subscription からアカウントを認証する方法も用意されています。

アカウント単位の認証情報の管理と、エージェントごとの設定を分けて扱えます。利用できるサブスクリプションやモデルは、ランタイムの対応状況とアカウントの権限によって異なります。既存のサブスクリプションを接続しても、利用上限がなくなったり、Computer のその他の費用が含まれたりするわけではありません。

## チャネル、実行環境、モデルをつなぐ構成

![Mosoo Computer の概念アーキテクチャ。チャットチャネルから Chat SDK、Agent Driver を経由し、クラウド上の Harness とモデルサブスクリプションへ接続する](/blog/blog/introducing-mosoo-computer/architecture-en.png)

*元の構成を保った英語版の概念図です。図中のサブスクリプションは構成上の例であり、利用できる組み合わせは製品画面とランタイムの対応状況によって異なります。*

左から順に、Vercel Chat SDK がチャネルのメッセージと返信を統一し、Mosoo Agent Driver が入力、イベント、Session を扱います。Agent Harness は推論、ツールの利用、タスクの実行ループを担います。クラウド環境には、永続ファイルシステム、Shell、必要に応じて稼働する Linux コンテナがあります。モデルへのアクセスは、Harness が対応する方法で接続します。

この役割分担により、「どこで話すか」「どう仕事を実行するか」「どのモデルを使うか」を、それぞれ発展させられます。チャネルを変えても作業環境を作り直さずに済み、新しいランタイムにも共通の接続先を用意できます。

## 最初の会話から始める

Mosoo は、エージェントの能力をアプリケーションに組み込む開発者に向けた製品です。Mosoo Computer は、エージェントと直接仕事をする人に向けた製品です。使い方が異なるからこそ、それぞれに合う導線が必要です。

まずはエージェントを一つ作り、モデルを設定して、Web Console から最初のメッセージを送ってみてください。その後、普段使うチャネルを接続します。残しておきたいファイル、仕事上の約束、設定を、少しずつ環境に蓄積していきます。

次の仕事を、前の仕事が残した土台から始められるように。それが Mosoo Computer の目指す体験です。
