loading="lazy" decoding="async" className="absolute inset-0 h-full w-full object-cover object-center" /> </div> </div> <div className="prose-mosoo"> <blockquote> <p>Follow the notes upon the journey. At first sight marks one’s destiny. Return lies within the hasty keys.</p> </blockquote> <p>A few months ago, I was moving between customer sites, talking through our New Agent Design in Workflow.</p> <p>The questions kept repeating: why not OpenClaw? How is this different from Hermes Agent?</p> <p>It was not the first time I felt a little lost.</p> <p>Eventually I realized the confusion was not about one tool. It was about a boundary we had not named clearly enough: when is Agent Work just a delivery, and when should it become part of a production system?</p> <p>For many consumer scenarios, building a component library ahead of time is too expensive.</p> <p>If the need is one-off, and you are not sure the same problem will appear again in three months, Claude Code or Codex is often enough. You do not need to abstract first. You do not need to build an app before delivering the result.</p> <p>Sometimes I tell customers to make the problem smaller.</p> <p>“This does not need to be so complicated. Claude Code can solve it. If the problem comes back, write a skill. That may be the smallest useful investment.”</p> <p>I still believe that.</p> <p>But another thing slowly became visible: countless personal PCs started growing fragmented Agent solutions.</p> <p>They were experiments, but also artifacts. They depended on local environments, Session History, context, file copies, MCP tools, and skills.</p> <p>I can finish the task on my computer. If your environment matches mine, you can replay my experiment.</p> <p>But if this is how Agent artifacts move, what are they? Fast-moving goods? A local performance that only works on one stage?</p> <p>That was the real turn in our journey.</p> <p>We are not trying to platform every piece of Agent Work. Quite the opposite: we want to respect the threshold.</p> <p>In an image, grayscale describes how bright or dark a pixel is. Usually 0 is pure black, and 255 is pure white.</p> <p>Agent Apps have a similar threshold.</p> <p>Below it, the right answer is a one-off app, a skill, a local delivery, a place where you should avoid unnecessary complexity.</p> <p>Above it, the work becomes building, evaluation, deployment, A/B testing, and production feedback. It needs a lifecycle.</p> <p>Once you cross that line, the tools become scattered.</p> <p>Developers have to stitch together point solutions: sandboxes, Eval Harnesses, deploy scripts, logs, permissions, context, UI, and functions where most of the real behavior still lives inside Prompt strings.</p> <p>At that point, you are no longer using Codex or Claude Code to solve your own problem.</p> <p>You are using them to build a production solution for your customer.</p> <p>You live inside harnesses and dependencies. You open terminals, worktrees, or a new ADE, trying to keep the work moving.</p> <p>That is when I kept asking myself: why is there no framework-agnostic “Supabase” for this?</p> <p>Not to replace builders, but to remove repeated Agent Runtime hosting, deployment, isolation, and evaluation from every app.</p> <p>Before cloud computing, building software felt like buying land, building a house, and running the property yourself.</p> <p>You bought servers, switches, and storage. You put them into a machine room or IDC before you could talk about the application.</p> <p>Agent App development is beginning the same journey.</p> <p>We used to wrap tokens into LLM API Calls and treat them as the smallest compute unit.</p> <p>Now we are wrapping tokens into requests against a Cloud Agent.</p> <p>Local consumer demand represented by tools like Hermes or OpenClaw will continue. But more complex production demand will move toward Cloud Agents in Sandboxes.</p> <p>It needs higher concurrency, longer-running jobs, stronger isolation, and background tasks that can be created, paused, resumed, evaluated, and deployed.</p> <p>We are re-abstracting cloud machine resources into a Cloud Agent Session Lifecycle API that developers can call directly.</p> <p>That is what we are building.</p> <p>Not another Agent Demo.</p> <p>Not another Prompt Wrapper.</p> <p>It is a value judgment: once Agent Work crosses the threshold, it should be hosted, isolated, observed, and reused like a cloud resource.</p> <p>We call it <strong>Mosoo</strong>.</p> <p>The first piece of that work is now open source: Mosoo Agent Driver.</p> <p>It is the driver layer we use to make OpenClaw, Hermes Agent, Claude Code, and Codex speak a compatible Agent Session API.</p> </div> <hr className="my-16 border-[color:var(--border)]" /> <div className="flex items-center justify-between
